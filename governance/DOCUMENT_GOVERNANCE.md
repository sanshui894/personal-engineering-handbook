# Document Governance

## 文档分类

| 分类 | 目录 | 内容边界 |
|---|---|---|
| Governance | `governance/` | 维护、安全和协作规则 |
| Reference | `reference/` | 跨项目可复用的稳定知识与命令 |
| Learning | `learning/` | 学习解释、实验结论与待分类材料 |
| Runbook | `runbooks/` | 可重复执行且有安全边界的操作流程 |
| Infrastructure | `infrastructure/` | 带来源和核验日期的基础设施事实 |
| Case Study | `case-studies/` | 从项目中脱敏提炼的可复用案例 |

## 项目事实与通用知识

项目仓库负责源码、实时运行真相、项目治理和项目专属命令。本仓库只保存跨项目知识、脱敏基础设施档案和明确标注来源的案例总结。迁移不能改变原事实的含义，也不能让知识库成为项目 CURRENT 状态的替代权威。

## 状态与核验

- `CURRENT`：在最后核验日期有证据支持的当前档案。
- `HISTORICAL`：过去核验成立但不再表示当前状态。
- `PLANNED`：计划内容，不得写成已实现。
- `UNVERIFIED`：缺少现场证据或证据已过期。

动态事实和所有基础设施事实必须记录来源、最后核验日期、状态与敏感级别。来源可以是命令输出、项目文档、供应商控制台或 `USER_REPORTED`，但必须明确区分。

## 更新与历史

- 当前档案允许基于新证据更新。
- `VERIFICATION_LOG` 只能追加，不能删除、重排或重写旧记录。
- 当前事实变化时，更新清单并向核验日志追加新记录。
- 迁移后仍需保留来源项目链接或来源说明，便于回溯。
- 历史记录中的旧值保持原样，并标为 `HISTORICAL`。

重大目录重构、权威边界变化、公开范围变化或大批量迁移需要用户批准。
